## 摘要
部署异构多智能体机器人集群进行协同感知需要鲁棒的数据交换和可扩展的软件架构。然而，当跨设备分发密集传感器流时，标准ROS 2实现通常会出现网络饱和、命名空间冲突和严重的计算开销。为了解决这些瓶颈，我们提出了SFG-ROS，一个面向动态集群部署的资源感知多智能体软件框架。SFG-ROS通过三个主要贡献应对这些挑战。首先，基于模式的流量路由利用程序化全限定名称模式和定向Fast DDS路由，将高频智能体内流量与全局网络隔离。其次，按需集中式解码流水线自动卸载高带宽传感器数据解压缩，消除了本地消费者节点上的冗余处理。最后，与硬件无关的容器流水线动态适应异构加速器，无缝衔接开发环境与零接触、现场就绪的执行。我们使用配备LiDAR和立体深度摄像头的轮式和腿式机器人集群评估该框架。实验结果表明，SFG-ROS将网络流量限制在$\mathcal{O}(1)$，并通过用轻量级IPC替代冗余解压缩，将每个订阅者的CPU扩展代价比标准ROS 2降低了72.3%，同时保持低延迟。最后，我们在宽松许可下发布SFG-ROS，可通过\href{https://iis-esslingen.github.io/sfg-ros}{iis-esslingen.github.io/sfg-ros}获取。

## Abstract
Deploying heterogeneous multi-agent robot fleets for collaborative perception requires robust data exchange and scalable software architectures. However, standard ROS 2 implementations often suffer from network saturation, namespace collisions, and severe computational overhead when distributing dense sensor streams across devices. To address these bottlenecks, we present SFG-ROS, a resource-aware multi-agent software framework designed for dynamic fleet deployments. SFG-ROS addresses these challenges through three primary contributions. First, schema-driven traffic routing isolates high-frequency intra-agent traffic from the global network using a programmatic fully qualified name schema and targeted Fast DDS routing. Second, an on-demand centralized decoding pipeline automatically offloads high-bandwidth sensor data decompression, eliminating redundant processing across local consumer nodes. Finally, a hardware-agnostic container pipeline dynamically adapts to heterogeneous accelerators, seamlessly bridging development environments with zero-touch, field-ready execution. We evaluate the framework using a fleet of wheeled and legged robots equipped with LiDAR and stereo depth cameras. Experimental results show SFG-ROS bounds network traffic to $\mathcal{O}(1)$ and, by replacing redundant decompression with lightweight IPC, reduces the per-subscriber CPU scaling penalty by 72.3\% versus standard ROS 2, all while maintaining low latency. Finally, we publish SFG-ROS under a permissive license, available via \href{https://iis-esslingen.github.io/sfg-ros}{iis-esslingen.github.io/sfg-ros}.

## 1. 论文的核心问题与整体含义
- **核心问题**：异构多机器人编队在密集传感器环境下协同感知时，标准 ROS 2 实现存在严重的扩展性瓶颈，主要表现为：
  - 网络饱和：分散发现机制在智能体数量增加时引发 UDP 组播风暴。
  - 命名空间冲突：多智能体间话题、服务、TF 帧 ID 容易发生混淆。
  - 冗余计算：多节点同时订阅同一压缩传感器流时，每个节点独立解压，导致 CPU 负载线性增长。
- **研究背景**：智能工厂网格（Smart Factory Grids）等场景需要动态、灵活的分布式生产网络，由轮式、腿式、人形等多类机器人构成协作集群，实时共享高带宽感知数据。现有框架（如 Open-RMF、FogROS 2 等）虽在编排或云卸载层面有进展，但未从底层解决 ROS 2 中间件的可扩展性、资源浪费和异构部署等问题。
- **整体含义**：提出 SFG-ROS，一个资源感知的多智能体软件框架，通过“全局压缩、本地原始”的通信架构和按需集中解码等机制，在保持低延迟的同时实现网络流量 $\mathcal{O}(1)$ 有界化和 CPU 扩展开销大幅削减，为资源受限的异构集群提供可复现的零接触部署方案。

## 2. 方法论成要素
SFG-ROS 围绕四个核心贡献展开：

- **模式驱动的流量路由（要求1）**
  - 采用全限定名称（FQN）模式 `T = (s, a, c, d, r)`，其中包含范围 `s`（Local/Global）、智能体 `a`、组件 `c`、数据流 `d`、资源 `r`。通过 `RosFqnBuilder` 类在代码层面强制规范命名，避免字符串拼接错误。
  - 利用 Fast DDS 路由器，依据 FQN 前缀（如 `rt/tf`、`rt/global/*` 等）执行路由策略 $\pi$：将本地域 $D_i$ 与全局桥接域 $D_0$ 双向转发全局流量，其余话题仅限本域通信，从而实现智能体内高频流量与跨智能体流量的物理隔离。

- **按需集中解码流水线（要求2）**
  - 引入 `AgentDecoder` 节点作为动态解码代理。原本多订阅者场景下，每个订阅者都需经历网络接收与解码完整过程：$c_{\text{base}} = \sum (c_{\text{net}} + c_{\text{dec}})$；SFG-ROS 将其改为：$c_{\text{proposed}} = c_{\text{net}} + c_{\text{dec}} + |S| \cdot c_{\text{ipc}}$（$c_{\text{ipc}} \ll c_{\text{dec}}$），解压仅执行一次，后续通过轻量级 IPC 分发。
  - `AgentDecoder` 监听 ROS 2 图事件和发现事件，按本地订阅实时加载/卸载解码组件（使用 composable node 容器），做到资源即用即取、不用即释放。同时利用 FFmpeg 插件实现硬件加速 H.264 编码，对深度图像采用无损 RVL 压缩，并全部采用 best effort QoS 避免数据积压。

- **硬件无关的容器部署（要求3）**
  - 三层 Docker 架构：硬件依赖层（动态检测 CUDA/ROCm 等选择基础镜像）、中间适配层（ROS 2 Humble, FastDDS, FFmpeg 等）、应用层（智能体特定依赖与 colcon 工作区挂载）。
  - 双容器编排（Docker Compose）：智能体栈容器 + 专用 DDS 路由容器。集成 systemd 服务实现开机自启；支持 VS Code 开发容器配置，提供 IntelliSense、调试、生命周期钩子等，实现开发到现场的无缝过渡。

- **时空同步与可视化工具（要求4）**
  - 实现 Rerun 数据查看器的 ROS 2 桥接，支持动态添加可视化器、QoS 配置和插件化消息融合（如同步 Image 与 CameraInfo）。
  - Vicon Bridge：解决官方接收器不能重映射帧 ID 和 TF 树根不匹配的问题，通过 `frame-via-proxy-frame` 机制计算并发布正确的 `Tmap→agent/base`。
  - 多智能体轨迹规划器：支持 SE(3) 姿态定义路点，可自动对齐朝向，通过 YAML 序列化，并发布到 ROS 2 动作服务器。

## 6. 主要结论与发现
- SFG-ROS 的网络流量与订阅者数量解耦，保持恒定的 $\mathcal{O}(1)$ 带宽占用（~4 Mbps）。
- CPU 扩展开销大幅降低：每个额外订阅者的 CPU 惩罚从 6.5% 降至 1.8%，降幅 72.3%。
- 发现时间在小规模集群中基本恒定（0.8–2.9 秒），网络流量比标准 ROS 2 低 1.8 个数量级。
- 增加的延迟开销极小：端到端延迟仅增加 2.6 ms；订阅到首帧延迟因组件动态实例化而增加约 1.9 倍（从 570 ms 到 1095 ms），属于一次性可接受成本。

## 7. 优点
- **系统性设计**：将命名、路由、解码、部署与可视化统一于一个框架，针对 ROS 2 底层缺陷提供了多层次解决方案。
- **“全局压缩、本地原始”范式**：巧妙平衡了网络效率与本地计算实时性。
- **代码强制命名规范**：程序化 FQN 构建器消除了人工命名错误，保证路由策略的有效执行。
- **动态解码资源管理**：利用组件动态加载和 IPC 替代冗余解压，资源利用率高，且易于扩展到其他传感器类型。
- **异构部署友好**：动态基础镜像选择与 systemd 集成，实现了真正的“零接触”现场部署。
- **工具链完整**：包括增强的可视化桥、Vicon 精确同步和轨迹规划器，提升了多智能体系统的研发效率。
- **开源与可复现**：代码公开，实验配置详实，利于社区验证。

## 8. 不足与局限
- **实验规模偏小**：仅验证到 6 个智能体和 10 个订阅者，无法评估框架在更大规模集群（如数十个机器人）下的表现。
- **场景单一**：所有测试均在室内静态场景进行，未包含动态障碍物、智能体移动或网络波动等真实工况。
- **依赖特定中间件**：架构基于 Fast DDS，虽然提及未来考虑 Zenoh 等替代方案，但当前泛化性受限。
- **冷启动延迟增加**：订阅到首帧延迟增大约 1 倍，对于需要极速响应的突发生感知场景可能构成影响。
- **缺少横向对比**：实验仅与标准 ROS 2 对比，未与 FogROS 2、Open-RMF 等其他多智能体框架进行直接性能对照。
- **生产部署限制**：colcon 工作区挂载方式更适合开发，缺乏不可变的包分发机制和安全的 OTA 更新流程，文中虽提及未来 CI/CD 集成，但当前未实现。
- **安全与容错考量不足**：未探讨 DDS 桥接的单点故障风险或网络安全机制。
