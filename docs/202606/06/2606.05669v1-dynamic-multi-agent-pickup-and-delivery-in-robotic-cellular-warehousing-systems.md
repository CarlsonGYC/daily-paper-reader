## 摘要
机器人单元仓储系统(RCWS)引发了多智能体取送货(MAPD)过程，机器人在此过程中为每个订单顺序收集多个库存单位(SKU)。与假设静态任务的经典MAPD模型不同，实际仓库操作通常涉及动态订单演化，即在订单执行过程中可能会追加新的SKU。受此实际需求驱动，本文首次考虑了内部订单演化的动态多智能体取送货问题。基于令牌传递范式，我们提出了两种事件触发的在线重规划算法。第一种是动态令牌传递，通过添加订单分解和基于优先级的令牌调度在订单更新时执行局部重规划，同时保证无碰撞执行。第二种是协作令牌传递，进一步使空闲机器人能够机会主义地协助新增取货任务，从而提高系统级效率。在RCWS环境中的仿真结果表明，与静态和非协作基线相比，所提出的方法显著降低了订单流经时间。

## Abstract
Robotic Cellular Warehousing Systems (RCWS) give rise to multi-agent pickup and delivery (MAPD) processes in which robots sequentially collect multiple stock-keeping units (SKUs) for each order. Unlike classical MAPD formulations that assume static tasks, real warehouse operations often involve dynamic order evolution, where new SKUs may be appended to an order while it is being executed. Motivated by this practical requirement, this letter formulates the Dynamic Multi-Agent Pickup and Delivery problem considering internal order evolution for the first time. Building on the token passing paradigm, we propose two event-triggered online replanning algorithms. The first, Dynamic Token Passing, performs localized replanning upon order updates through add-order decomposition and priority-based token scheduling while preserving collision-free execution. The second, Cooperative Token Passing, further enables idle robots to opportunistically assist newly added pickups, improving system-level efficiency. Simulation results in RCWS environments demonstrate that the proposed methods significantly reduce order flowtime compared with static and non-cooperative baselines.

## 1. 论文的核心问题与整体含义
- 传统多智能体取送货（MAPD）问题假设所有任务在规划前已完全确定且不会在执行过程中变化，这难以满足机器人单元仓储系统（RCWS）中订单在线追加 SKU 的现实需求。
- 本文首次将“内部订单演化”定义为动态 MAPD（Dynamic‑MAPD）问题：同一订单在执行中可能被追加新商品，导致任务目标集实时变化，机器人需要在执行过程中动态重规划路径，同时保证无碰撞和订单截止期限。
- 研究意义在于弥合经典 MAPD 模型与实际仓库操作之间的鸿沟，提升动态环境下多机器人协作的响应能力与整体效率。

## 2. 论文提出的方法论
### 2.1 总体框架
- 基于经典的“令牌传递（Token Passing, TP）”协调机制，引入事件触发的在线重规划。
- 共享一个全局令牌，存储所有机器人当前预留路径与任务分配；当订单更新事件发生时，受影响的机器人获得令牌并进行重规划，提交新路径后释放令牌。

### 2.2 动态令牌传递（Dynamic‑TP）
- **绑定模式**：每个订单固定由一台机器人负责，新增 SKU 必须由同一机器人完成。
- **事件触发流程**：
  1. 监控所有订单的更新指示器 γ_k(t)。
  2. 构造受影响订单集合 K_upd(t)，计算每个订单的剩余截止时间 Δd_k(t) = d_k − t，并按升序建立优先级队列（越紧急越优先）。
  3. 机器人按优先级获取令牌，将剩余未取 SKU 与新增 SKU 合并为 O_new^{k⋆}(t)。
  4. 使用 A* 在时间扩展图上规划从机器人当前位置出发、遍历所有取货点并到达交付终点的无碰撞路径（PATH1）；若 PATH1 失败，则使用 PATH2 生成无碰撞的部分路径至安全端点，并将订单保留待未来重规划。
  5. 将新路径写入令牌，释放令牌，继续执行。
- 这一方法避免了从头开始全新任务指派，只进行局部调整，计算开销小。

### 2.3 协作令牌传递（Cooperative‑TP）
- **协作模式**：允许多台机器人合作完成同一订单的新增 SKU。
- **触发条件**：当订单更新时，首先计算绑定机器人独立完成全部剩余任务的基础时间 ETA_base，再计算仅完成原有剩余任务所需的时间 ETA_rem；同时为每一台空闲机器人计算从当前位置取走全部新增 SKU 并送达目标交付站的时间 ETA_add_j。
- 协作激活条件：∃ aj∈A_idle，使得 max(ETA_add_j⋆, ETA_rem) < ETA_base。即合作完成比单独完成更快。
- 若条件满足，将新增 SKU 分配给该空闲机器人，更新令牌中的任务序列，二者分别按紧急度排队重规划。
- 本质上是一种基于预计完成时间的任务交换与并行决策机制。

### 2.4 复杂度分析
- Dynamic‑TP 每次更新事件的计算复杂度约为 O(C_plan)，其中 C_plan 为单次 A* 路径规划代价（∼O(N log N)）。
- Cooperative‑TP 每次更新额外评估所有空闲机器人的路径，复杂度约为 O((2+n_idle)·C_plan)。
